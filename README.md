# AstroPhone

스마트폰 렌즈의 촬영 프레임과 여러 천체의 상대 위치를 비교하는 Python 3.12 데스크톱 프로그램입니다. 사진 생성이나 촬영 가능성 판단은 하지 않습니다.

**API 키는 필요 없습니다.** 사용하는 PhoneCameraData, SIMBAD, JPL Horizons 모두 키 없이 조회할 수 있습니다. 회원가입·로그인·키 발급이나 `.env` 파일 작성 없이 아래 명령으로 실행하면 됩니다. 인터넷 연결은 필요합니다.

## 설치와 실행

UV가 설치된 Windows에서 이 프로젝트 폴더를 열고 실행합니다.

```powershell
uv sync --locked
uv run python astrophone.py
```

`.python-version`은 Python 3.12를 지정하고, `uv.lock`은 패키지 버전을 고정합니다. 외부 패키지는 `requests` 하나이며 GUI는 Python의 `tkinter`입니다. API 키와 `.env` 설정은 필요 없습니다. 인터넷 연결이 필요합니다. `tkinter` 불러오기와 실제 창 생성은 별개이며 Tcl/Tk가 정상 설치된 Python이어야 합니다.

제조사 → 기종 → 렌즈를 선택합니다. 별·은하는 **SIMBAD**, 태양계 천체는 **Horizons**를 고르고 정확한 이름/식별자를 입력합니다. 예: `Vega`, `M 31`, `Sun`, `Moon`, `Mars`. 프로그램에는 이 이름이나 천체 ID 목록이 저장되어 있지 않습니다. Horizons가 여러 대상을 반환하면 이름과 ID를 확인해 선택합니다.

천체를 추가한 뒤 목록에서 선택하고 **선택 천체를 화면 중심으로**를 누르면 조준 방향이 바뀝니다. **줌 슬라이더를 움직이면 1~10배 범위에서 조절되며, 옆에 현재 배율이 소수점 한 자리로 표시됩니다.** 줌을 바꾸면 기존 천체 데이터를 이용해 촬영 프레임을 즉시 다시 그리며 API를 재호출하지 않습니다. 사진 비율(4:3·16:9·1:1)도 변경할 수 있습니다. 시각은 **한국 시간, YYYY-MM-DD HH:mm:ss**로 입력하고 **KST 시각 적용**을 누릅니다. 선택 삭제와 전체 삭제도 가능합니다.

## API와 코드 구조

| 파일 | 역할 |
|---|---|
| `astrophone.py` | 실행 진입점, 사용자 입력, 후보 선택, 작업 스레드와 결과 큐 |
| `astro_api.py` | HTTP 요청, JSON/CSV 해석, 수치·단위 검증, KST→UTC 변환 |
| `astro_view.py` | GUI 배치, 구면 투영, 화각·크롭 계산, 프레임 포함 판정 |

Python 파일은 총 3개이고 각각 200줄 이내입니다. 다중 상속이나 GUI 프레임워크는 사용하지 않습니다.

| API | 실제 사용하는 필드와 단위 |
|---|---|
| [PhoneCameraData 목록](https://phonecameradata.com/api/models-index) / `api/models/{slug}` | `items`의 `brand`, `name`, `slug`; `item.cameras`의 `type`, `focalLength` |
| [SIMBAD TAP · 공식 Harvard 미러](https://simbad.cfa.harvard.edu/simbad/sim-tap/sync) | `ident.id`와 정확히 일치하는 대상의 `main_id`, `ra`, `dec`, `galdim_majaxis`; 응답 메타데이터의 도·각분 단위를 검사 |
| [JPL Horizons](https://ssd-api.jpl.nasa.gov/doc/horizons.html) | 지구 중심 `500@399`, ICRF 적경·적위(도), 각지름(각초), 지정 UTC 시각; API 후보의 ID로 재조회 |

PhoneCameraData의 [iPhone 15 Pro 상세 사양](https://phonecameradata.com/en/models/iphone15pro)은 API와 같은 13·24·77mm를 **Equiv. Focal**로 표시합니다. 이를 35mm 환산 초점거리로 사용하며, 없는 제조사·렌즈·초점거리를 보완하지 않습니다.

화면의 **SIMBAD**는 [공식 Harvard 미러](https://simbad.cfa.harvard.edu/)의 TAP API에 연결됩니다. 원본 서버의 연결 시간 초과가 확인되어, 실제 조회가 성공한 공식 미러로 통일했습니다. 서버를 따로 선택할 필요가 없습니다. 웹페이지 스크래핑은 하지 않습니다. 프로그램에서 조회한 천체·기종 정보는 메모리에만 유지됩니다.

## 핵심 계산

- 35mm 프레임 대각선 `D = √(36² + 24²) mm`에 맞춘 이상적인 4:3 프레임의 폭·높이는 `4D/5`, `3D/5`입니다. 16:9는 세로, 1:1은 가로를 잘라냅니다. 이 기준은 계산 모델이며 휴대폰 센서 사양을 추정한 값이 아닙니다.
- 환산 초점거리 `f`, 줌 `z`, 크롭된 변 길이 `s`일 때 화각은 `2 × atan(s / (2fz))`입니다. 디지털 줌은 프레임 크롭으로만 처리합니다.
- 적경·적위를 단위벡터로 바꾸고 중심 방향의 접평면에 투영합니다. 동·북 성분을 중심 성분으로 나누는 **노모닉 투영**이므로 직선 광선의 카메라 프레임과 비교할 수 있고 적경 0°/360° 경계도 처리합니다. 북쪽은 위, 동쪽은 왼쪽입니다.
- 각분은 60, 각초는 3600으로 나누어 도로 통일합니다. 제공된 장축/각지름을 지름으로 하는 외접원을 그리고, 구면에서 네 프레임 경계와의 각거리를 검사해 원 전체의 포함 여부를 판정합니다. 각크기가 없으면 점과 **중심 안·크기 미제공**으로 표시합니다.
- HTTP 요청은 daemon 스레드에서 실행하고 Tk 갱신은 메인 스레드의 큐 폴링으로 처리합니다. 시각 갱신은 모든 요청이 성공한 경우에만 한꺼번에 반영합니다. 실패하면 기존 좌표와 화면에 표시된 계산 시각을 유지합니다.

지구 중심 구도를 보여 주므로 관측 장소의 달 시차·대기 굴절·지평선·날씨·빛공해를 계산하지 않습니다. SIMBAD 좌표의 고유운동은 전파하지 않으며 Horizons의 ICRF 좌표와 함께 미리보기 용도로 사용합니다. 천체 외형은 장축 기준 외접원으로 표시하므로 타원 모양이나 위상은 재현하지 않습니다. 중심에서 90° 이상 떨어진 천체는 접평면에 투영할 수 없어 목록에 별도로 표시합니다. 렌즈 왜곡·손떨림 보정·기종별 실제 크롭은 API가 제공하지 않아 반영하지 않으며 화면 화각은 이상적인 근사입니다. 로그인·저장·자동완성·추천·사양 수동 보완 기능은 없습니다.
